# 구현 설계 및 요구사항 대응

차량 로그 수집·정제·조회 요구사항과 현재 구현의 대응 관계를 정리한다. 기본 제공 문서와 예제 파일은 저장소에 포함하지 않는다.

## 범위

차량 로그 관리 앱으로, 현재 화면 구성은 단일 DashBoard다. 별도의 인포테인먼트 홈과 사이드바 데이터 업로드 메뉴는 제외하고 상단 로그 업로드 버튼으로 파일을 등록한다. 사용자 ID 필터(F207)까지 포함한다. 실제 구현 소스와 프로젝트 문서만 버전 관리한다.

| 번호 | 우선순위 | 요구사항 | 구현 위치 / 검증 방법 |
|---|---|---|---|
| F201 | 필수 | 파일을 행 단위로 원시 컬렉션에 저장 | `dist/app.js`, `dist/services.js`, `functions/lib/upload.js`. 빈 줄을 제외한 모든 행을 보존, 동시 저장 8개, 진행률·실패 건수·실패 재시도 제공 |
| F202 | 필수 | 생성 즉시 서버리스 정제 | `functions/index.js`의 `onDocumentCreated`, `functions/processor.js`. 서울 리전 배포 및 실제 실행 검증 완료 |
| F203 | 필수 | 정제 로그를 구조화된 전용 컬렉션에 저장 | `telematics_logs/{원시 문서 ID}`. KST 원본을 Timestamp로 저장, 측정값·문자·좌표·품질 정보 구분 |
| F204 | 필수 | 새로고침 없는 최신순 로그 표시 | `onSnapshot` 구독, 최신순 정렬, DashBoard 직접 진입, 헤더·사이드바·고정 하단 바. 원명세의 Home → Setting 진입은 현재 화면 구성에서 제외 |
| F205 | 필수 | 날짜·등급·키워드 복합 검색 | `functions/lib/query.js`, `dist/app.js`. 한국 시간 기준 시작일/종료일 포함, 메시지·사용자 대소문자 무시 검색 |
| F206 | 필수 | 등급별 시각적 구분 | INFO 민트, WARNING 황색, ERROR/CRITICAL 적색, DEBUG 청색. 색상과 함께 등급 이름 표시 |
| F207 | 심화 | 사용자 ID 기반 필터 | 실제 로그의 `user`로 선택지를 생성하고 다른 조건과 결합 |

## 처리 흐름

```text
TXT/LOG 선택 → 행/품질 미리보기 → 업로드
  └─ raw_telematics_logs → Functions → telematics_logs → onSnapshot
                                     └─ 형식 오류: 원문 유지 + rejected/parseError
```

화면은 설정된 Firebase 프로젝트에 자동 연결한다. 연결 오류 발생 시 재연결 버튼을 제공한다.

## 정제 규칙과 예제 코드 개선

- 원시 시간에는 시간대가 없으므로 **Asia/Seoul(KST, UTC+09:00)**로 해석한다. 실제 달력 날짜·시각을 검증한 다음 UTC Timestamp로 저장한다.
- `Accel`의 음수는 감속이므로 보존한다. 엔진 온도도 음수를 허용한다. 속도·거리·연비·GForce는 음수를 잘못된 값으로 분류한다.
- 측정값이 비어 있으면 `null`과 `missingFields`로 표현한다. 로그 종류에 원래 존재하지 않는 필드는 만들지 않는다.
- 잘못된 숫자·단위·브레이크·좌표·중복 키는 `invalidFields`에 기록한다. 해당 행 자체는 조회 가능하게 보존한다.
- `Brake`, `Event`, `Impact`를 문자 값으로 보존한다. 위치는 위도와 경도를 각각 숫자로 저장한다.
- `WARN`은 `WARNING`으로 정규화한다. INFO, WARNING, ERROR, CRITICAL, DEBUG를 지원한다.
- 헤더/시간/사용자/등급/메시지가 파싱 불가능하면 원시 저장 후 `rejected` 처리한다. 정제 로그로 잘못 저장하지 않는다.
- 이벤트 중복 전달은 트랜잭션의 처리 상태와 동일 문서 ID로 방지한다. 일시적 DB 오류는 상위로 전달한다. 비용이 수반되는 장기 자동 재시도는 비활성화했으므로 pending 원문은 함수 로그 확인 후 별도 복구한다.
- 행 원문 SHA-256 + 파일 내 동일 원문의 반복 순번으로 업로드 ID를 만든다. 부분 파일과 전체 파일이 겹쳐도 같은 기록은 재사용하며 한 파일 안의 반복 행은 보존한다. 이전 파일 기반 ID도 원문과 반복 순번을 대조해 재사용한다. 부분 실패 재시도에는 준비 단계에서 만든 ID와 반복 순번을 유지한다.

10행 파일은 1,000행 파일의 첫 10행과 같다. 날짜별 건수는 7월 5일 225건, 6일 330건, 7일 345건, 8일 100건이다. 샘플의 충돌/에어백 이벤트는 제공된 실습 데이터이며 실제 차량 사고를 의미하는 자료로 해석하지 않는다.

## 검증 범위

`npm test`: 자체 작성 입력을 사용해 집계, 정제 경계값, 시간대, 복합 검색, 행 보존, 업로드 동시성/실패 재시도, 중복 트리거, 오류 기록 및 재시도 동작을 검사한다.

`npm run check`: JavaScript 구문, JSON 설정, HTML ID 연결, 정적 리소스 경로 및 브라우저/Functions 공통 모듈의 동일성을 검사한다.

실제 Firebase 프로젝트를 연결하여 Cloud Functions ACTIVE 상태, Firestore 사용자별 권한 규칙, 인덱스 쿼리, 익명 로그인과 업로드→정제→조회 실행을 검증했다. 결과는 `docs/firebase-connection.md`에 기록했다. 브라우저에서 전체 파일 업로드 완료와 실제 정제 로그 1,000건 조회를 확인했다. 먼저 저장한 10행과 전체 파일 간 중복은 생기지 않았다. 화면 캡처 검수는 수행하지 않았다. WebMCP는 지원 브라우저에서만 활성화되며 해당 컨텍스트에서의 동작 검증은 미실시다.

## 정렬과 상세 탐색

기록 시각·등급·사용자·메시지·속도·엔진의 열 제목으로 기본 → 오름차순 → 내림차순 → 기본을 순환한다. 기본은 최신순이며 정렬은 필터 결과 전체에 적용한 뒤 페이지를 나눈다. 등급은 심각도 순, 숫자는 수치 순, 문자열은 자연 정렬을 사용한다. 누락값은 방향과 관계없이 마지막에 표시한다. 날짜 범위 요약은 정렬 기준과 관계없이 실제 최솟값·최댓값을 표시한다.

행을 누르면 선택한 로그의 상세창을 표시한다. 열린 시점의 필터·정렬 결과를 기준으로 좌우 버튼과 방향키를 통해 페이지 경계를 넘어 탐색하며 첫 항목과 마지막 항목에서는 해당 방향 버튼을 비활성화한다. 업로드는 모든 행 저장 성공 시 창을 자동으로 닫으며 부분 실패 시 실패 행 재시도 화면을 유지한다.
